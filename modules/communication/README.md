# 板间 CAN 协议 v1

两板固件使用本项目定义的 CAN1 协议 v1，波特率 1 Mbit/s。部署前核对双方固件、CAN1 设备 ID 和物理连接。

| 方向 | 标准 ID | 消息 |
| --- | --- | --- |
| 底盘→云台 | 0x300、0x301、0x302 | 遥控命令三分片 |
| 云台→底盘 | 0x310、0x311、0x312 | 关节角与状态三分片 |

每帧 DLC=8，非扩展/RTR。data[0]=版本1，data[1]=8位消息序号，data[2..7] 是
18字节内容的连续6字节；ID 减起始 ID 得到片号0..2。同一消息三片使用相同序号，
每个新消息序号递增，255 后回到0。全部多字节字段小端，不直接序列化 C 结构体。

| 内容偏移 | 遥控命令 | 状态 |
| --- | --- | --- |
| 0 | bit0 remote_valid，bit1 arm，bit2 estop，其余0 | bit0 calibrated，bit1 motors_healthy，bit2 sensors_fresh，bit3 fault，其余0 |
| 1 | mode：0分离、1跟随、2小陀螺 | 0 |
| 2..5 | forward/left，各 int16，归一化值×10000 | yaw_joint，int32，rad×1000000 |
| 6..9 | yaw/pitch，各 int16，归一化值×10000 | pitch_joint，int32，rad×1000000 |
| 10..15 | 保留，必须0 | 保留，必须0 |
| 16..17 | CRC16，小端 | CRC16，小端 |

命令轴范围 [-10000,10000]。状态输入 Yaw 在 [-π,π]，Pitch 在 [-π/2,π/2]；
接收端容许端点的微小量化误差。

CRC16：poly=0x1021，init=0xFFFF，不反射，xorout=0。
校验顺序：**版本1、类型（命令0/状态1）、序号、内容字节0..15**。
测试包含由 Python binascii.crc_hqx 独立计算的固定校验向量。

## 接收语义

- Link_Init 显式配置组装超时和有效期，要求 `0 < 组装超时 < 有效期 < 2^31 ms`。
  云台命令接收为 20/100 ms，底盘状态接收为 50/100 ms。
- 允许乱序，同一片重复不推进进度。较新消息替换旧的不完整消息，超时丢弃未完成组。
- 已同步后接受序号增量1..127，拒绝重复/旧消息；发送频率和有效期须保证不跨半个周期。
  否则应缩短有效期或升级为更长序号。
- 只有完整、CRC正确、语义正确的新消息更新 last_rx_ms。
- 上电/超时后命令必须 arm=false 才能重新同步；状态无此要求。
  安全状态机仍要求回中并重新使能。CRC 不提供身份认证或恶意重放防护。
- Link_GetCommand 过期返回 false，同时输出 remote_valid=false、arm=false、estop=true。
- Link_Receive 返回 true 且命令 remote_valid=true 才是上板喂狗候选事件。
  状态、电机反馈、重复包、错误包、单片都不喂狗。无效遥控命令可以停机但不喂狗。

两板 CAN1 FIFO0 中断接收，主循环通过短临界区读取快照。底盘约每 10 ms 发命令，上板按 20 ms 调度状态，逐片提交并预留 Yaw 发送邮箱。分片入邮箱成功后仍需对端完整收齐并通过校验。上板仅在主循环消费新的有效遥控命令时刷新 IWDG。状态帧不喂狗。

跨板停机依赖有效急停命令、故障状态或各自超时。最新固件的通信故障和实机停机证据见[验收清单](../../docs/acceptance.md)。
